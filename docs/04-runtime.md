# 04｜Agent／Skills／Tools／Policies／Evidence 執行架構

## 元件契約
| 元件 | 工作 | 權限與失敗限制 |
|---|---|---|
| Orchestrator | 維護事件、調用職責技能、產生提案 | 無直接管理憑證；不能自改政策 |
| Skills | 收集、調查、處置規劃、驗證、報告 | 輸入／輸出有schema與版本；外部文字只作資料 |
| Connectors | 讀取具範圍的 API／日誌 | 分開讀寫身分；逾時與限流回明確錯誤 |
| Policy Gate | 判定每次行動是否可執行 | 模型外確定性規則；deny-by-default |
| Executor | 只接受核准的工具與參數 | 不接受任意 shell 字串；冪等鍵與執行收據 |
| Verifier | 獨立觀測威脅與業務結果 | 不把執行器的「成功」當成結果證據 |
| Evidence Store | 保存原始證據、雜湊、授權與結果 | 證據不可由被稽核者覆寫；資料分級與存取稽核 |

## 持續運作要求
事件佇列使用去重鍵（tenant＋來源事件ID）；工作狀態持久化。網路重試採退避與上限，寫入逾時先查實際狀態。每個資產變更使用鎖與冪等鍵，避免多個事件同時隔離與解除隔離。熔斷器監控失敗率、告警暴增與成本；超額暫停新變更，既有防護照常運作。

每個 task 記錄模型、規則、Skill、工具版本；同樣輸入不保證 LLM 字句完全相同，驗收以政策決策與可測量條件重現為準。多租戶資料、金鑰、記憶及索引實體或邏輯隔離。

## 工具選擇
採用四項共用元件與一份流程 Skill。Wazuh 負責安全營運、Wazuh MCP 負責介面、Trivy 負責軟體掃描、OPA 負責政策決策。具體來源、授權、版本候選與未驗證事項見 [工具清單](tool-catalog.md)。其他雲端、身分與備份系統沿用企業現有介面，按責任範圍逐項接入。

Defender 不等於 Defender for Endpoint；本版不假設付費企業隔離功能可由內建 Defender 直接提供。

## 工具入場表
每個工具填：官方來源、release/tag/commit、下載雜湊、授權全文位置、維護狀態、支援 OS、所需 scope、網路端點、敏感資料流、試行與回復結果。未填完不得進入可寫入環境。2026 年建立本文件不代表每項工具已有「2026 版」或完成版本查核。

## 證據契約
每筆包含 evidence_id、case_id、source、collector、asset_id、event_time、collected_at、timezone、工具版本、原始檔位置、SHA-256、存取分級、保留期限、衍生關係及收集錯誤。
雜湊只能偵測相對變更，不能單獨證明來源真實；正式部署配合身分驗證、時間同步、受保護記錄與必要簽章。原始證據留私有儲存；公開 Repo 只放合成資料與去識別報告。
