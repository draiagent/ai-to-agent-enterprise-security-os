# 企業導入 AI，資安也要從「提醒」走向「負責」

企業開始讓 AI 查資料、整理報表、讀取文件，甚至跨系統完成工作。這時，資安管理要回答的問題也變了：誰知道 Agent 接觸了什麼？誰決定它能做什麼？出現異常時，誰能提出證據並完成處置？

我提出「企業自主資安 Agent」的設計方向：讓 Agent 在企業授權的範圍內，持續整理安全訊號、調查風險、提出處置方案，並追蹤結果。自主程度由政策、資產與動作共同決定，每一步都要留下可檢查的產物。

先用 VAD 看懂全貌：企業有哪些設備、帳號、資料、雲端服務、程式與 AI 工具？各由誰負責？資料從哪裡進來，行動由哪個介面執行？把責任與權限畫清楚，後續工作才有依據。

再用 VAC，把一次資安任務拆成八步。

**第一步，資產盤點。** 找出要保護的設備與軟體，確認擁有人及重要性。沒有範圍的任務，很容易查了很多，卻沒查到真正重要的地方。

**第二步，持續監測。** 整理日誌、設定與登入紀錄，同時確認資料是否完整。沒有警示，不一定代表沒有風險，也可能是資料沒有送進來。

**第三步，風險偵測。** 由端點監控與軟體掃描工具分工，找出需要進一步確認的訊號，並說明影響範圍。

**第四步，證據調查。** 串起時間線、帳號、程序與連線紀錄。Agent 必須把事實、推論與未知分開，避免把合理猜測寫成確定結論。

**第五步，授權決策。** 檢查這次行動是否在核准範圍內、能否回復、會不會影響營運。高風險處置交由人員核准，政策判斷由模型外的機制執行。

**第六步，受控處置。** 只執行核准的防禦動作，保留操作紀錄與回復方式。工具回報成功，還不能直接畫上句點。

**第七步，獨立驗證。** 重新讀取狀態或複掃，確認風險是否降低、服務是否正常。證據不足，就保留待驗證。

**第八步，持續改善。** 回顧誤報、漏報與處置成本，提出規則改善；經審核與測試後，再更新作業程序。

工具選擇也要有分工：Wazuh 負責安全營運資料，MCP 提供受控介面，Trivy 補上軟體掃描，OPA 承擔政策決策。流程技能保留一份，讓同一套工具在不同步驟共用，減少重複維護。

企業可以從一台測試設備、一件唯讀調查開始。先證明資料看得見、判斷有依據、結果驗得出，再逐步擴大授權。衡量成效時，也要記錄人力、時間與模型成本。

**用 AI 理解風險，用 Agent 落實受控防禦。** 好的資安 Agent，應該能說清楚做了什麼、為何能做，以及憑什麼判定完成。
