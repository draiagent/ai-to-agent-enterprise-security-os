# 使用方式

## 先完成一個可驗收的事件

1. 閱讀 README 與 VAC 圖卡，選一台企業明確授權的測試資產。
2. 填寫 [事件範本](../examples/incident-template.json)：範圍、擁有人、證據來源、禁止動作、截止時間。
3. 依 [權限模型](../policies/authority.md) 設定本次最高 A0／A1，先維持唯讀。
4. 把合成資料與事件範本交給 [唯一資安營運 Skill](../skills/security-operations/SKILL.md)。依使用平台的技能載入方式提供該檔；本 Repo 未驗證各平台安裝器。
5. 要求分開輸出事實、推論、未知與建議。只有提出建議，不代表取得處置權限。
6. 按 VAC 07 的獨立驗證要求檢查證據；缺件保留 UNKNOWN。
7. 由資產擁有人確認後，才進入下一階段的連接器試行。

## 可直接使用的任務指令

> 請依本專案 VAD／VAC 與 security-operations Skill，分析 incident-template.json。只處理指定測試資產，不執行系統變更。依八步列出已有證據、缺件、建議、政策決策及驗收條件；無證據的項目標示 UNKNOWN，最後輸出事件報告。

## 離線示範

在 Repo 根目錄，使用 Python 3.10 以上：

```bash
python3 examples/policy_demo.py
python3 tests/check_docs.py
```

第一個指令執行 16 項合成政策案例；第二個檢查文件。它們均不連線企業端點，也不會安裝 Wazuh、Trivy、MCP 或 OPA。

## 示例：遠端工具已停用

輸入只說「遠端工具已停用但仍安裝」。Agent 應要求服務、程序、自動啟動、登入、連線與掃描證據，不能僅因軟體名稱判定惡意，也不能僅因停用宣稱安全。範圍外操作不得執行；資料不足保持 UNKNOWN。完整案例見 [SEC-001](../cases/SEC-001.md)。

## 完成條件

資產範圍清楚、證據可追溯、處置有授權、驗證獨立於執行器、業務功能正常、回復方式可用、缺口有責任人與期限。任何重要未知尚未排除，不宣告整個環境安全。
